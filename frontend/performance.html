How to read the timings

Document wait includes the network and the HTML response. API server time covers the processing measured by Alishan. DB round trips include time waiting for and talking to PostgreSQL. API outside server is an estimate that can also include proxies and queuing. Page ready is measured after initial content rendering where available. Startup data ready marks when the initial data setup finishes, including cached data. Key content visible estimates the first paint of the Dashboard totals or Inventory list. Data to key content is the time between these marks. Route preparation measures how long the tap waited for the page HTML and route script to be available. A previously warmed route can show near zero. Older readings can identify document loads when those timings were recorded. Their first and repeat SPA visits remain unclassified. Visit details can also show the wait for the shared Reports store, report scope calculation, report rendering and setup, device cache initialization, and the startup bundle. The bundle can come from cache or the network. The phase timings may overlap. A dash means the metric was unavailable or did not apply.
